## 검증과 배포의 경계

원격 dev `d2e01901db3c19f86fa748ab22489b0590f0d96e`에 이번 변경만 통합했다. 기존 미배포 CDN/embed/upload 변경과 개인 발행 스크립트는 제외했다. [호환성 표](compatibility-and-measurement.md)는 API·RSS·slug 계약을 연결한다.

로컬 회귀 검사는 환경파일을 복사하지 않은 mock 후보에서 실행한다. 실제 SDK 검사는 수집 요청을 차단하거나 로컬 204로 응답했으며 Google 수집기로 보내지 않았다. 15개 시나리오에서 sentinel 유출 0건, 정상 최초 page_view 1회와 SPA 추가 1회를 관찰했으나 GA 보고서 반영은 검증하지 않았다. 민감 URL/폼/외부 이동 이후 같은 document의 계측 중단에 따른 누락이 있다. 외부 자동 수집 설정 변경 시 재검사가 필요하다.

dev workflow는 배포 후 source SHA/hash·실행 image ID를 대조하고 컨테이너 내부 GET으로 health·페이지·robots·게시글 API를 확인한다. Access 로그인 HTML 200은 정상 health가 아니다. 새 후속 smoke 실패는 workflow 실패를 표시하지만 추가 자동 rollback을 보장하지 않는다. production rollback은 mock 실패 주입 검증이며 실제 운영 복구를 실행하지 않았다.

실제 로그인·관리자 DB 쓰기, 법적 고지/동의, GA console 설정, 청구·사용량, 백업 복원과 외부 알림 수신은 운영 추가 확인이다. [운영 runbook](operations-runbook.md)의 확인 표를 사용하며 미확인 수치를 추정하지 않는다.

상세 원장과 로그는 로컬 `/tmp/raven-implementation/{public,admin,technical}-status.json`, `candidate-pending.md`, `candidate-checks/`의 작업 artifact이며 Git 추적 파일이 아니다. 이 문서와 검사 스크립트는 저장소에서 추적한다. 최종 실행 revision·Actions URL·결과는 배포 보고로 연결한다.
