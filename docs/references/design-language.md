## 원칙

- **raw hex/px 금지** — 앱 코드는 CSS 변수 토큰만 참조. 색의 정의 자리는 `src/styles/tokens.css` 하나다.

## 색 토큰

팔레트의 근거는 브랜드 마크다. 까마귀 깃털은 검지 않고 각도에 따라 청록에서 보라로 번지는
광택이 있으며, 마크가 그 현상을 그린 것이다. 잉크는 중성 검정이 아니다 — 마크의 글로우가
중성 회색 위에 번지면 때가 탄 것처럼 보여서, 중성색 전부를 액센트와 같은 계열로 옅게 물들였다.

괄호 안은 `--color-canvas` 대비.

| 토큰                     | 값        | 대비    | 용도                                       |
| ------------------------ | --------- | ------- | ------------------------------------------ |
| `--color-canvas`         | `#080a12` | —       | 페이지 배경                                |
| `--color-canvas-2`       | `#0c0f1a` | —       | 코드블럭 등 한 단 가라앉은 면              |
| `--color-surface`        | `#121724` | —       | 카드면                                     |
| `--color-text-strong`    | `#ffffff` | 18.94:1 | 목록 행 hover에서 제목이 한 단 오를 때     |
| `--color-text`           | `#e9eef6` | 16.97:1 | 제목·강조어                                |
| `--color-text-reading`   | `#c3cddd` | 12.33:1 | **길게 읽는 본문**                         |
| `--color-text-secondary` | `#9aa6bc` | 8.05:1  | 보조·캡션                                  |
| `--color-text-muted`     | `#7d8aa4` | 5.69:1  | 날짜·읽기시간 같은 메타                    |
| `--color-border`         | `#1f2738` | 1.32:1  | hairline (낮은 것이 정상)                  |
| `--color-border-strong`  | `#2c3750` | 1.67:1  | hover 보더                                 |
| `--color-accent`         | `#3ed9c0` | 11.19:1 | 링크·강조어·상태                           |
| `--color-accent-hover`   | `#66e6d2` | —       | accent hover/active                        |
| `--color-accent-deep`    | `#5b3fe0` | 3.04:1  | **그라디언트·빛 전용. 글자에 쓰지 않는다** |
| `--color-ink-ghost`      | `#3a4356` | 1.99:1  | 진입 인트로 전용(장식이라 AA 밖)           |

- 본문 크기 이하로 쓰이는 색은 전부 WCAG AA(4.5:1)를 넘긴다. 카드면 위에서도 넘긴다.
- **UI 액센트는 청록 하나로 고정한다.** 색이 옮겨 가는 것은 마크와 빛이 스치는 자리에서만
  일어난다. 둘 다 변하면 액센트가 둘이 되어 서로를 깎는다.
- **브랜드색은 면이 아니라 글자에 쓴다.** 면에 브랜드색을 깔면 강조가 강조를 잃는다.
- accent를 헤드라인 강조어에 쓰는 것은 허용한다(히어로의 한 구절). 섹션 레이블에는 쓰지 않는다.
- `--code-dot-1~3`은 macOS 창 버튼의 관습색이라 계조에 참여하지 않는다. 예외지만 tokens.css에
  모아 둔다 — 예외는 예외인 채로 한곳에 보여야 관리된다.

### 본문 밝기를 왜 두 단으로 나눴나

제목이 16.97:1인데 본문을 `--color-text-secondary`(8.05:1)로 두면 최대 대비의 절반이라
본문만 잠긴 것처럼 보인다. 다크에서 본문을 낮추는 것은 헐레이션을 막으려는 것이지 절반까지
내리려는 게 아니다 — 읽기 화면 레퍼런스의 본문은 대개 최대 대비에 가깝다(overreacted 15.9:1).
그래서 `--color-text-reading`을 따로 두고 `secondary`는 메타에 남겼다.

### 면과 계조

**섹션 배경을 통째로 바꿔 구획하지 않는다.** 히어로를 뒤집어 봤더니 캔버스 대비가 가능한
최대치라 스크롤할 때 흑백이 슬램처럼 부딪혔다. 진폭을 낮춘 톤 패널도 답이 아니다 — 옅은
패널 위에서 `--color-text-muted`가 AA 미달로 떨어진다.

대신 **계조를 세울 자리를 만든다.** 행이 컨테이너에 직속이면 면을 쌓을 데가 없어 hairline
말고 쓸 수단이 없다. 카드가 있으면 그 안에 계조가 생긴다.

- 카드로 세우는 것: 단건(반복 없음)과 동급 3~4개 묶음
- 평평하게 두는 것: 목록 행 — 읽는 화면은 밀도, 쓰는 화면은 여백이다
- 카드 = 1px 보더 + `--radius` + `--color-surface` + `--shadow-card`
- **상태마다 표현은 하나씩.** hover는 배경(또는 좌측 획), 정적 구분은 보더
- 흐린 보더(불투명도를 낮춘 보더)를 쓰지 않는다. 저대비 모니터에서 사라진다
- 어두운 바탕에서는 그림자가 잘 안 보이므로 깊이는 그림자가 아니라 면의 밝기 차로 만든다

## 읽기 조판

**글 상세와 About은 같은 것을 하는 화면이다.** 두 CSS 모듈이 각자 크기를 적어 두는 바람에
18px과 16px로 갈려 있었다. 한 곳에서 정하고 양쪽이 참조한다.

| 토큰              | 값                          | 실효값  |
| ----------------- | --------------------------- | ------- |
| `--reading-size`  | `var(--fs-18)`              | 18px    |
| `--reading-lh`    | `var(--lh-body)`            | 1.7     |
| `--reading-color` | `var(--color-text-reading)` | #c3cddd |

제목 아래 붙는 한두 줄 설명은 읽는 문단이 아니라 항목의 부연이라 한 단 작다(16px/secondary).
읽기 조판 토큰을 거기까지 끌어 쓰지 않는다.

## 타이포 토큰

랜딩은 크게 키우는 대신 **작고 촘촘하게** 간다. 초대형 조판(실측 102px)은 화면을 채우는 게
아니라 오히려 비웠다 — 같은 폭에 들어가는 정보가 줄기 때문이다.

- 스케일: `--fs-56 … --fs-12`.
- 굵기: `--fw-title`(700). `base.css`가 `h1~h6`에 전역 적용하므로 모듈에서 다시 선언하지 않는다.
- 행간: `--lh-display`(1.15) · `--lh-title`(1.22) · `--lh-tight`(1.1) · `--lh-lead`(1.5) ·
  `--lh-dense`(1.6, 랜딩 본문) · `--lh-body`(1.7, 읽기 화면).
- 자간: `--ls-display`(-0.032em) · `--ls-title`(-0.028em) · `--ls-body`(-0.02em).
  **한글은 자폭이 커서 음수 자간을 주지 않으면 제목이 성겨 보인다.**
- **mono는 숫자·해시·시각·영문 레이블에만 쓴다.** IBM Plex Mono에 한글 글리프가 없어
  한글을 mono로 지정하면 시스템 폰트로 조용히 폴백된다.
- 섹션 레이블(Eyebrow): `--fs-12`, 굵기 600, `--ls-eyebrow`(0.01em), `--color-text-secondary`.
  **자연어 한글로 쓴다.** 영문 대문자 mono를 쓰던 시절엔 `uppercase`가 한글에 아무 효과가
  없어 규칙이 반만 작동했고, 한글 내비게이션과 레지스터도 갈렸다.
  이 규칙은 결정 뒤 두 번 되살아났으므로 `check:design`이 강제한다.
- `text-wrap`: 제목은 `balance`, 본문은 `pretty`. `base.css`가 전역 적용한다.

## Spacing Scale

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 24px;
--space-6: 32px;
--space-7: 48px;
--space-8: 64px;
--space-9: 96px;
--space-10: 160px;
```

- **랜딩·본문의 섹션 간격은 `--space-9`(96px)다.**
- `--section-gap`(160px)은 남아 있지만 **읽기 화면 하단 내비에는 쓰지 않는다.** 바로 위
  `ArticleAside`가 이미 상단 보더로 경계를 세우고 자기 여백을 갖는데 160px을 더하면
  공유 아이콘 하나 밑으로 화면 한 뼘이 빈다. **경계를 두 번 세우지 않는다.**
- `--outer`는 900px 이하에서 `--space-5`로 축소.

## 레이아웃 토큰

| 토큰               | 값       |
| ------------------ | -------- |
| `--w-container`    | `1080px` |
| `--w-reading`      | `700px`  |
| `--radius`         | `14px`   |
| `--radius-control` | `10px`   |
| `--radius-sm`      | `8px`    |
| `--radius-pill`    | `999px`  |

- 컨테이너는 1400px에서 1080px로 좁혔다. 헤더 알약이 콘텐츠 가장자리와 정렬되면서 전폭 바가
  되지 않아야 하고, 1400px에서는 글 목록 태그가 컨테이너 끝까지 밀려 제목과 시선이 끊겼다.
- 읽기 폭은 780px에서 700px로 좁혔다. 읽기 화면 레퍼런스 6곳(overreacted 632 · emilkowal.ski
  644 · rauno.me 672 · joshwcomeau 686 · toss.tech 700)의 본문 폭이 632~700px에 모여 있고
  780px은 그 바깥이었다 — 18px 한글로 한 줄 43자다.
- 라운딩은 절제된 3단 — 카드 14 / 컨트롤 10 / 작은 요소(칩·이미지) 8.

### 좌우 여백은 라우트가 책임진다

**읽기 열은 `max-width`로 자기 폭을 정하지만 좌우 여백은 갖지 못한다.** 뷰포트가 읽기 폭보다
좁아지는 순간 글자가 화면 끝에 붙는다. 데스크톱에서는 어긋나지 않아 눈으로는 안 보인다.

- 모든 라우트 최상단(`page` · `loading` · `not-found` · `error`)은 `Container`를 거치거나,
  `Container`를 품은 것으로 확인된 컴포넌트(`StatusScreen` · `ArticleSkeleton`)에 위임한다.
- **로딩 스켈레톤과 본 화면은 같은 래핑을 쓴다.** 한쪽만 빠지면 로딩이 끝나는 순간 좌우로
  `--outer`만큼 튄다.
- 이 규칙은 2026-08-10에 세 화면(치명), 2026-08-15에 `blog/[slug]`에서 깨졌다.
  그래서 `check:design`이 강제한다 — 파일마다 고치는 것으로는 세 번째를 막지 못했다.

## 브레이크포인트

**640 · 900 · 1280 셋만 쓴다.** 한때 560·640·820·900·1280 다섯 종이 파일마다 흩어져 있었다.

| 폭     | 무엇이 바뀌나                                           |
| ------ | ------------------------------------------------------- |
| 640px  | 경력 행 1열 · 하단 내비 1열 · 푸터 열 간격 · 마크 bleed |
| 900px  | 히어로 1열 · `--outer` 축소                             |
| 1280px | 목차 기둥 등장                                          |

마크 bleed(컨테이너 여백을 무효화해 화면 끝까지 흘리는 것)에는 상한이 없다. 넓은 화면에
걸리면 마크가 뷰포트 폭 그대로 커지므로(860px에서 876px짜리 새가 됐다) 640px 이하로 묶는다.

## 텍스트 줄바꿈 (CJK)

전역 `word-break: keep-all`(어절 단위) + `overflow-wrap: break-word`(긴 영문·URL 강제 개행).

## 모션 규칙

- `--dur`: 220ms · `--dur-slow`: 240ms(상태 전환의 상한).
- `--ease`: `cubic-bezier(0.22, 1, 0.36, 1)`. 트랜지션에 `ease` 키워드를 직접 쓰지 않는다.
- hover: 배경 한 단 상승, 또는 목록 행의 좌측 획.
- card: `translateY(2px)` · page: fade + 12px.
- parallax·과한 모션 사용 금지. `motion`(`motion/react`)은 이 규칙 안에서만.
- `prefers-reduced-motion` 반드시 존중 — 애니메이션이 정보를 쥐고 있으면 안 된다.
- 유리(헤더 알약)는 **스크롤한 뒤에만** 켠다. 비칠 것이 없는 순간에 켜면 그건 유리가 아니라
  그냥 알약이다. Apple HIG도 Liquid Glass를 기능 레이어에만 두고 평평한 배경 위에 쓰지 말라고 한다.

## 접근성

- `:focus-visible`은 `base.css`가 전역으로 준다. 링크의 밑줄을 지웠으므로 이건 선택이 아니다.
- **본문으로 건너뛰기 링크가 body 첫 자식이다.** sticky 헤더와 목차가 본문 앞을 막고 있어
  키보드로는 매 페이지 그것들을 지나야 했다. 화면 밖에 두되 탭 순서에서 빼지 않는다.
- **행이 반응하면 행이 눌려야 한다.** 목록 제목에 hover 색만 주고 링크는 따로 두면 가짜
  인터랙션이다. 제목을 `<a>`로 만들고 `::after`로 행 전체를 덮는다 — 진짜 `<a>`를 넓히는
  방식이라 가운데클릭·⌘클릭·우클릭이 그대로 산다.
- **선택 상태는 같은 모양 위의 변화다.** 활성 클래스가 기본 클래스를 대체하면 선택된 항목만
  여백·보더·라운딩을 잃어 상태 차이가 아니라 종류 차이로 읽힌다.

## 미결

- **라이트 모드.** 읽기 화면 레퍼런스는 측정한 7곳 중 6곳이 라이트다(다크는 제품 소개 화면인
  linear뿐). 다크 캔버스는 브랜드 마크에서 나온 이 사이트의 고유성이라 버리지 않되, 읽기
  화면에 선택지가 없다는 것이 레퍼런스 대비 유일하게 벌어진 축이다. 토큰이 한 겹으로 모여
  있어 `:root` + `[data-theme]` 레이어만 추가하면 컴포넌트는 손대지 않는다. **결정 대기.**
- **브랜드 마크 정밀도.** 지금 마크는 손으로 그린 근사치다. 원본은 `main-legacy1`의
  `public/assets/logo.png`(1024px)이며 벡터로 따서 polygon 좌표를 교체해야 정확해진다.
