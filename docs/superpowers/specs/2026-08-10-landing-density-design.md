## 1. 문제

홈이 비어 보인다. 브라우저 실측으로 원인을 셋으로 분해했다.

1. **커버 이미지가 없으면 2열이 무너진다.** `LatestThinking`·`LatestBuild`가 각자 한 섹션을 차지하며
   `텍스트 | 이미지` 2열을 이뤘는데, `cover_image_url`이 없으면 `.noMedia` 분기로 미디어 열이
   사라져 두 섹션 모두 1열이 된다. 텍스트 폭은 46ch로 묶여 있고 컨테이너는 1400px이라
   **화면 오른쪽 절반이 통째로 빈다.** 이것이 주원인이다.
2. **히어로 아래가 224px 비어 있었다.** 히어로 `padding-bottom` 64px + 다음 섹션 `--section-gap` 160px.
3. **콘텐츠가 얇다.** 개발 환경은 `CONTENT_SOURCE=mock` 기본값으로 글 2개·프로젝트 1개,
   커버는 전부 `null`이다. 운영 API는 작성 시점에 502/404였다.

`profile.ts`에 실제 데이터(경력·스택·현재 하는 일)가 있는데 홈이 전혀 쓰지 않고 있었다.

## 2. 제약

콘텐츠가 앞으로 얼마나 쌓일지 모른다. 따라서 **"최근 글 5개를 뿌린다" 같은 양 의존 해법은 쓸 수 없다** —
글이 2개면 오히려 더 빈약해 보인다. 블록은 데이터 유무와 무관하게 성립해야 한다.

## 3. 설계

### 3.1 블록이 자기 생존을 판단한다

`LatestWork`가 최근 글과 최근 프로젝트를 **한 섹션 2열**로 묶는다.

| 데이터        | 렌더                             |
| ------------- | -------------------------------- |
| 글 + 프로젝트 | 2열                              |
| 하나만        | 1열 전폭 (빈 열을 남기지 않는다) |
| 둘 다 없음    | 섹션 자체를 렌더하지 않는다      |

글과 프로젝트를 서로의 짝으로 세우면 **커버 유무와 무관하게 두 열이 찬다.** 커버가 있으면
각 열 안에서 이미지가 제목 위에 붙는다.

`LatestThinking`·`LatestBuild`는 삭제하지 않고 `<section>` 껍데기만 벗겨 열(`<article>`)로 바꿨다.
기존 테스트 8건이 그대로 유효하다.

### 3.2 프로필을 공용 레이어로 승격

`src/app/about/_components/profile.ts` → `src/constants/profile.ts`

홈과 About이 공유하므로 `_components`(표시 전용 private)에 둘 수 없다. `constants/`는 공용 하위
레이어라 `app/` 어디서든 참조할 수 있다.

**페이지별 역할 분담(중복 방지):**

- 홈 — `lead`·`now`만. "누가, 지금 무엇을."
- About — 전부. 서사·focus·경력·스택·연락처.
- **경력(`experience`)은 About 전용이다.** 홈에 요약본을 두면 같은 표가 두 곳에 생긴다.

### 3.3 홈 구성 — 골격을 섹션마다 다르게

| #   | 블록       | 배경               | 골격                                 |
| --- | ---------- | ------------------ | ------------------------------------ |
| 1   | Hero       | **잉크(풀블리드)** | 디스플레이 헤드라인 + ProcessDiagram |
| 2   | LatestWork | 밝음               | 균등 2열                             |
| 3   | Exploring  | 밝음               | 번호 행 목록 (01/02/03)              |

같은 리듬을 반복하지 않는다는 직전 감사(#8)의 결론을 유지한다.

`AboutTeaser`는 제거했다 — About 페이지가 이미 그 역할을 하고, 헤더·푸터에 About 링크가 있다.

### 3.3.1 잉크 히어로 (화려함을 어디서 얻는가)

"와이어프레임 같다"는 지적에 대한 답. 헌장이 **accent를 interaction 전용으로 묶고 그림자를
금지**하므로 색·그림자로는 갈 수 없다. 남은 가장 큰 시각 장치는 **명도를 뒤집는 것**이다.

- 히어로만 배경을 `--color-ink`로 뒤집고 화면 끝까지 쓴다(`Container`는 안쪽).
- 헤드라인은 `--fs-display`(`clamp(2.75rem, 8vw, 8rem)`)로 뷰포트를 따라 커진다.
- 반전 토큰과 적용 방식(토큰 재바인딩 + `color` 명시 필수)은
  [design-language](../../references/design-language.md)의 "반전(잉크) 블록"이 정본이다.

**전환은 1회뿐이다.** 처음에는 히어로·Exploring 둘을 잉크로 두어 밝음/어두움을 네 번
오갔는데, 스크롤 내내 배경이 뒤집혀 어수선했다. 임팩트는 첫 화면 한 번이면 충분하다.

### 3.4 여백

- 히어로 `padding-bottom`: 96 → 32px
- `LatestWork` `margin-top`: `--section-gap`(160) → `--space-9`(96)

결과: 히어로 콘텐츠 → hairline 128px. 나머지 섹션 리듬과 일치한다.

**SSOT 드리프트 기록:** `design-language.md`는 섹션 간격을 `--space-10`(160px)로 규정하지만
실제 코드는 거의 전부 `--space-9`(96px)를 쓴다. 160px를 쓰던 곳은 이 한 군데뿐이었다.
지금은 96px로 통일했으나 **문서와 코드가 여전히 어긋나 있다** — 어느 쪽을 정본으로 삼을지는
별도 결정이 필요하다. `--section-gap` 토큰은 현재 `SiteFooter`만 쓴다.

## 6. 남은 것

- **콘텐츠 얇음은 코드로 해결되지 않는다.** mock 글에 `summary`가 없어 왼쪽 열이 오른쪽보다
  짧다. 운영 데이터에 요약과 커버가 있으면 이 격차는 사라진다.
- `--section-gap` 토큰의 정본 값 결정 (§3.4 드리프트).
- 리스트 요소 다수가 `list-style: none`만 두고 `padding` 초기화가 없어 UA 기본 좌측 패딩 40px을
  갖는다. 이번 범위 밖.
