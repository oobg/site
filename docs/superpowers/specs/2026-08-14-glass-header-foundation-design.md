# 글래스 헤더와 CSS 파운데이션 재작성 (설계문)

- 작성일: 2026-08-14
- 상태: 설계 확정, 구현 전
- 브랜치: `feat/glass-redesign`
- 관련 SSOT: [architecture](../../references/architecture.md) · [design-language](../../references/design-language.md)
- 선행 스펙: `2026-08-10-landing-density-design.md` — 그 문서가 세운 팔레트·계조 결정을 이 문서가 부분적으로 이어받는다

---

## 1. 요구

사용자가 요구한 것은 셋이다.

1. 상단 헤더를 **sticky 글래스모피즘**으로. 느낌은 아이폰 사파리 탐색 탭처럼 동글동글한 알약.
2. **기본 CSS를 전부 지우고** 처음부터 다시 쌓는다. `modern-normalize`를 기반으로.
3. 전체 느낌을 바꾼다.

범위 확인 과정에서 "전부"의 뜻을 물었고, 사용자는 **`*.module.css` 39개를 포함한 전면 재작성**을
선택했다. 토큰만 갈아끼우는 안과 토큰·globals만 비우는 안은 명시적으로 기각됐다.

## 2. 제약과 함정

### 2.1 글래스모피즘은 KB에 슬롭 신호로 등록돼 있다

`shared · 안티슬롭 · 「AI 슬롭이란? 텍스트·코드·이미지·영상 안티슬롭 완전 정리」`가
"둥근 카드 + blur 배경(glassmorphism·backdrop-blur)"을 AI 티의 대표 신호로 명시한다.
사용자가 알고 선택한 방향이므로 진행하되, **클리셰가 되지 않게 하는 것이 설계의 과제**다.
이 문서의 §4가 그 답이다.

### 2.2 밝은 캔버스에서는 통상적인 글래스 레시피가 뒤집힌다

사용자가 참조로 제시한 값은 어두운 배경을 전제한다. `--color-canvas`(#F7F8FA) 위에서 실측한 결과:

| 통상 레시피                              | 밝은 캔버스에서의 문제                                    | 이 문서의 값                          |
| ---------------------------------------- | --------------------------------------------------------- | ------------------------------------- |
| `background: rgba(255,255,255,.2)`       | 흰 20%가 캔버스와 밝기가 거의 같아 면이 생기지 않는다     | 틴트 `.44`                            |
| `border: 1px solid rgba(255,255,255,.3)` | 밝은 바탕에서 보이지 않는다                               | 어두운 헤어라인 `rgb(26 31 38 / .07)` |
| (없음)                                   | `saturate()`가 빠지면 뒤의 색이 죽어 회색 반투명판이 된다 | `saturate(190%)`                      |
| `box-shadow: 0 8px 32px rgba(0,0,0,.1)`  | day0의 "보더 중심, 그림자는 흔적만"과 충돌                | `0 6px 20px -8px rgb(26 31 38 / .22)` |

흰 선은 경계가 아니라 **위쪽 안쪽 하이라이트**(`inset 0 1px 0`)로만 쓴다.

### 2.3 토큰을 지우면 39개 모듈이 조용히 깨진다

CSS 변수가 미해결로 떨어지면 색·간격·폰트가 사라지는데 **빌드는 통과한다.** 타입체크도 린트도
잡지 못한다. 그래서 §6의 검증 절차가 필요하다.

### 2.4 머지 전까지 사이트는 무스타일이다

전면 재작성이므로 사이클 1을 끝내도 랜딩·목록·상세는 스타일이 없다. `feat/glass-redesign`
브랜치에서 사이클 6까지 끝낸 뒤 머지한다. `main`은 현재 상태를 유지한다.

## 4. 재질 — 무엇을 슬롭과 가르는가

GitHub 토픽 `glassmorphism`을 별 순으로 조사한 결과, 상위 두 리포가 전부
**애플의 iOS 26 Liquid Glass를 WebGL 셰이더로 재현**한다.

| 리포                  | 별  | 기법                                                     |
| --------------------- | --- | -------------------------------------------------------- |
| `naughtyduk/liquidGL` | 822 | 페이지를 래스터화한 뒤 WebGL로 굴절·색수차·베벨·스페큘러 |
| `ybouane/liquidglass` | 383 | WebGL — 프레넬·림 스트로크·다중 광원                     |
| `css.glass`           | 449 | 2021년식 blur+tint 제너레이터                            |
| `themesberg/glass-ui` | 407 | 2021년식 CSS 라이브러리                                  |

사용자가 참조한 값은 3·4위 계열(2021년식)이고, 정작 사용자가 원한 사파리 탭바는 이미
Liquid Glass로 넘어갔다. **그 차이가 §2.1의 슬롭 신호와 갈리는 지점이다.**

- 2021년식은 **면 하나**다. 흐린 배경 위 반투명 판 한 장.
- Liquid Glass는 **가장자리가 다르게 동작한다.** 유리는 정면보다 림에서 더 굴절하고 더 반사한다.

상위 두 라이브러리는 채택하지 않는다. 페이지를 캔버스로 래스터화하는 비용과 접근성 위험이
개인 사이트 헤더에 맞지 않는다. **아이디어만 순수 CSS로 이식한다 — 런타임 의존성 0.**

| 요소     | 구현                                                    |
| -------- | ------------------------------------------------------- |
| 베벨 림  | `::before`의 4방향 `inset` box-shadow                   |
| 프레넬   | `::before`의 `radial-gradient` — 가장자리로 갈수록 밝음 |
| 색수차   | 좌우 림에 아주 옅은 청/적 `inset`. **눈에 띄면 실패다** |
| 스페큘러 | `::after`의 `linear-gradient`가 포인터를 따라 이동      |

스페큘러를 **늘 흐르는 애니메이션으로 두지 않는다.** 자동으로 반짝이면 장식이 되고,
손을 따라오면 재질이 된다.

### 4.1 SVG 변위 굴절은 채택하지 않는다

`backdrop-filter: url(#filter)`로 실제 굴절을 넣는 안을 만들어 비교했으나 기각한다.
사파리와 파이어폭스가 이 값을 받지 않으며, **미지원 시 선언 전체가 버려져 유리가 통째로
사라진다** — 조용한 폴백이 아니다. 사파리 느낌을 목표로 하면서 사파리에서 안 걸리면 본말전도다.

## 5. 설계

### 5.1 파일 구조

```
src/app/globals.css
  @import 'modern-normalize/modern-normalize.css';
  @import '../styles/tokens.css';
  @import '../styles/base.css';
```

`src/styles/reset.css`는 삭제하고 `base.css`로 대체한다.

### 5.2 base.css — normalize가 하지 않는 것만

`modern-normalize`는 box-sizing, body margin, 폼 요소 폰트 상속, 표·인용 정규화를 처리한다.
**하지 않는 것**만 여기 둔다.

```
*                    margin: 0
ul, ol               padding: 0; list-style: none
img/picture/svg/video display: block; max-width: 100%
a                    color: inherit; text-decoration: none
h1~h6                font-weight: var(--fw-title); text-wrap: balance
p, li                text-wrap: pretty
body                 배경·색·폰트·min-height 100dvh·flex column
                     word-break: keep-all; overflow-wrap: break-word
::selection
:focus-visible       outline 2px solid var(--color-accent)
```

`ul, ol { padding: 0 }`은 KB에 미해결로 남아 있던 항목을 해소한다 —
`personal · raven.kr · 「리스트 요소 다수가 list-style: none만 두고 padding 초기화가 없어
UA 기본 좌측 패딩 40px을 그대로 갖는다」`.

**본문 마크다운의 불릿은 `ArticleBody`에서 복원한다**(사이클 4). 전역에서 리스트를 죽이고
읽기 화면에서만 되살리는 방향이며, 그 반대는 목록·칩·내비게이션마다 초기화를 반복하게 된다.

### 5.3 색 토큰은 유지한다

2026-08-10 커밋에서 캔버스 대비를 직접 계산해 AA를 통과시킨 팔레트다. 버리면 그 검증을
다시 해야 하고, KB의 `--color-text-muted` 대비 미달 사건이 반복될 위험이 있다.

**전체 느낌의 변화는 유리·컨테이너 폭·라운딩·모션이 낸다.** 사용자가 이 판단을 확인했다.

### 5.4 바뀌는 토큰

```css
--w-container: 1080px; /* 1400px에서 축소 */

--header-top: var(--space-4); /* 16px */
--radius-pill: 999px;

--glass-tint: 0.44;
--glass-blur: 14px;
--glass-sat: 190%;
--glass-edge: rgb(26 31 38 / 0.07);
--glass-shadow: 0 6px 20px -8px rgb(26 31 38 / 0.22);
```

컨테이너를 1080px로 좁히는 이유는 두 가지다. 헤더 알약이 콘텐츠 가장자리와 정렬되면서도
전폭 바가 되지 않아야 하고, KB에 `「글 목록 태그가 1400px 컨테이너 끝까지 밀려 제목과
시선이 끊긴다」`가 미해결로 남아 있다. 이 변경이 그 항목도 함께 해소한다.

### 5.5 헤더

```
<div data-sentinel />              1px. 관찰 대상
<header sticky top:--header-top>   컨테이너 폭 1080
  <nav.pill data-stuck>            실제 유리
    <a.wordmark>raven.kr</a>
    <div.links>글 · 프로젝트 · About</div>
```

**스크롤 이벤트 리스너를 쓰지 않는다.** 헤더 위 1px sentinel을 `IntersectionObserver`로
관찰해 `data-stuck`을 토글한다. 스크롤마다 콜백이 도는 구조를 피하려는 것이다.

상태는 둘뿐이다.

| 상태                          | 유리                         | 높이      | 워드마크 |
| ----------------------------- | ---------------------------- | --------- | -------- |
| 최상단 (`data-stuck=false`)   | 꺼짐 — 글자만 캔버스 위에 뜸 | 패딩 넉넉 | 16px     |
| 스크롤 후 (`data-stuck=true`) | 켜짐                         | 납작      | 14.5px   |

최상단에서 유리를 끄는 이유: 비칠 것이 없는 순간에 유리를 켜면 그것은 유리가 아니라
그냥 흰 알약이다. **폭은 두 상태에서 변하지 않는다** — 사용자가 폭 수축안을 보고 기각했다.

`'use client'`는 `SiteHeader`에만 준다. 나머지는 RSC를 유지한다.

### 5.6 접근성과 모션

- `prefers-reduced-motion: reduce` — 상태 전환을 즉시로. 지금 `tokens.css`가 이 미디어 쿼리에서
  `--dur: 0ms`로 떨어뜨리고 있고, 토큰을 다시 쓸 때 이 규칙을 그대로 가져간다
- 스페큘러는 `(pointer: fine)`이고 reduced-motion이 아닐 때만 포인터를 추적한다. rAF로 스로틀
- `-webkit-backdrop-filter` 병기 (사파리)
- 유리 위 글자는 틴트 `.44` 상태에서도 AA를 넘겨야 한다. 최악의 경우는 어두운 콘텐츠가
  바로 밑을 지날 때이므로 **구현 시 그 상태로 대비를 실측한다**

## 6. 검증

빌드가 통과해도 화면이 깨질 수 있는 작업이라(§2.3) 통상 게이트에 하나를 더한다.

1. `pnpm typecheck`
2. `pnpm lint`
3. `pnpm test`
4. `pnpm build`
5. **정의 없는 `styles.X` 참조 전수 검사** — KB에 이 검사가 4건을 잡았고 그중 2건은 같은
   세션에서 새로 만든 것이라는 기록이 있다(`personal · raven.kr`). 39개 모듈을 다시 쓰는
   작업에서 정확히 그 결함이 나오는 자리다. 스크립트를 되살려 `package.json`에 넣는다
6. 헤더 육안 검증 — 최상단·스크롤 후 두 상태, 라이트 화면에서

KB에 `「이번 감사는 렌더 화면이 아니라 소스 전수 읽기로 수행했고 육안 검증은 하지 않았다」`가
risk로 남아 있다. 6번을 생략하지 않는다.

## 7. 이 문서가 다루지 않는 것

- 사이클 2~6의 화면 설계 — 각자 스펙을 갖는다
- 다크 모드 — 사용자가 라이트 유지를 선택했다
- 팔레트 교체 — §5.3
- 배경 그라데이션(색면) — 유리를 돋보이게 하지만 §2.1의 슬롭 신호에 정확히 해당한다.
  비교 화면을 제시했고 사용자가 켜지 않았으므로 **기본은 색면 없음**으로 간다. 명시적
  기각은 아니므로, 구현 후 유리가 밋밋하면 다시 꺼낼 수 있는 카드로 남긴다
